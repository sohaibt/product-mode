## Decision: Ship slash commands as skill files installed by init
Date: 2026-11-07
Context: The checklist and decision log need a separate terminal CLI, but people work in the agent chat. Claude Code, Codex, and Cursor all read SKILL.md files now.
Options considered: [`product-mode init` copies skill files into the project, Claude Code plugin installed with /plugin install]
Choice: `init` copies `/preflight` and `/decision` into `.claude/skills/` and `.agents/skills/`, because it reuses the existing CLI, covers all three agents, and is the smaller change. A public plugin name is harder to change. `trivial` stays CLI-only because it is a code check. `init` never overwrites an existing skill with the same name.
Reversibility: two-way door, except the command names, which users learn
Revisit trigger: Users ask for a Claude Code plugin, a command name clashes in practice, or Sohaib does not use /preflight in his own projects within 2 weeks of the 1.1.0 release.

Update 2026-11-07: Added a third command, `/product-review`, the same day instead of waiting for the 2-week dogfood check. Sohaib chose it over waiting. It is the one command that does something the rules file does not: an on-demand check of a plan or diff against all seven principles. It is read-only and applies the "When to Skip" table, so a typo fix gets a one-line "Ready". The other per-principle commands (`/frame`, `/assumptions`, `/tradeoffs`, `/done`, `/instrument`) stay unbuilt until usage shows a need. The 2026-11-21 revisit now covers all three commands.

Update 2026-11-14: Expanded `/product-review` after a whole-product dogfood exposed missing stage calibration, source traceability, cross-artifact consistency, and outcome-validation checks. Kept one command and seven principles; broader product reviews gain targeted checks while routine changes retain proportionate rigor. Added authored review scenarios in `examples/product-review.md`; static inspection and CLI tests do not establish better agent reviews. Reversibility: two-way door. Revisit trigger: recorded fresh-agent runs reveal missed contradictions, over-flagging of early plans, unsupported absence claims, or unnecessary friction in routine reviews.

Update 2026-11-14 (skill upgrades): Added `product-mode init --upgrade-skill product-review` so existing installations can receive the revised skill. Default `init` remains non-destructive; only the explicit option replaces local edits to the named skill in both agent directories. The user approved this public CLI option after reviewing the tradeoff. Reversibility: implementation is a two-way door, but the option becomes costly to remove once users rely on it. Revisit trigger: real upgrade usage shows that the overwrite warning is insufficient, the targeted option is too restrictive, or users need a safe way to preserve customized skills.

Update 2026-11-16: Compared fresh-agent Pricebite reviews using published 1.2.0 and local 1.3.0. The 1.3.0 run caught a dropped outcome threshold and an unsourced claim, but also asserted that the product worked without observed validation, changed the payment sample and threshold inconsistently, flagged analytics while saying they were unnecessary, and treated potentially compatible roles as contradictory. Tightened evidence, stage-calibration, coherence, and recommendation self-check rules, and added a built-product regression case. This single comparison does not isolate the skill from model or session variation and is not evidence of improved behavior. Reversibility: two-way door. Revisit trigger: the next fresh Pricebite run or authored regression case reveals unsupported claims, unnecessary gaps, inconsistent thresholds, false contradictions, or an unbounded recommendation.
