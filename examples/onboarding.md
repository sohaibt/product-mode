# Add an onboarding checklist

Illustrative worked example. This is an authored scenario, not a captured model response or evidence of a customer outcome.

## Starting request

> Add an onboarding checklist so more users activate.

## The unresolved question

Checklist completion is a proxy. Users may tick every box without receiving value.

A useful question before coding:

> What observable action means the user received value, and how often does it happen today?

## A possible brief after clarification

- **User and problem:** New workspace owners need to complete their first useful workflow. This is a hypothetical definition to validate with the product team.
- **Why now:** Unknown. Ask for the trigger, evidence, or cost of waiting before implementation.
- **Smallest scope:** Guide users to one existing action that represents first value, with a way to resume it later.
- **Tradeoff:** A shorter flow covers fewer features but makes it easier to identify the step blocking first value.
- **Success metric:** The proportion of new workspace owners who complete the agreed first-value event within seven days. Record the current baseline before launch.
- **Measurement:** Track eligible new owners, exposure to the guide, and the first-value event. Compare cohorts or run a randomized test where practical. Watch errors, time to value, and support requests.
- **Reversibility:** Reversible behind a feature flag. Revisit if checklist completion rises while activation stays flat.

## What to check in your own agent session

Does the agent distinguish supplied facts from assumptions? Does it offer a smaller scope and identify a meaningful outcome before choosing implementation details? Different agents and prompts may do this without additional instructions; compare actual responses rather than assuming a difference.
