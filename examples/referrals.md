# Build a complete referral system

Illustrative worked example. This is an authored scenario, not a captured model response or evidence of a customer outcome.

## Starting request

> Build referrals with invite codes, credits, leaderboards, fraud detection, and an admin dashboard.

## The unresolved question

The proposed system assumes customers want to refer others and that rewards are necessary. Neither is established by the request.

A useful question before coding:

> What evidence says customers want to refer others, and what is the smallest pilot that would test it?

## A possible brief after clarification

- **User and problem:** A small SaaS team wants to learn whether existing customers will introduce another team. This is a hypothetical goal.
- **Why now:** Unknown. Ask for the trigger, evidence, or cost of waiting before implementation.
- **Smallest scope:** A small, explicitly opt-in referral pilot with a simple way to record introductions. Do not build a rewards engine yet.
- **Tradeoff:** Credits, leaderboards, and an admin dashboard add operational commitments before demand is known. A manual pilot takes staff time but tests demand sooner.
- **Success metric:** The proportion of pilot participants whose referrals become activated teams. Set a target only after agreeing on the cohort and activation definition.
- **Measurement:** Record pilot invitations, consented introductions, and referred-team activation. Review after the pilot window; watch support time and unwanted invitations.
- **Reversibility:** The pilot is reversible; promises of credits create obligations. Revisit automation if referral volume makes manual handling costly.

## What to check in your own agent session

Does the agent distinguish supplied facts from assumptions? Does it offer a smaller scope and identify a meaningful outcome before choosing implementation details? Different agents and prompts may do this without additional instructions; compare actual responses rather than assuming a difference.
